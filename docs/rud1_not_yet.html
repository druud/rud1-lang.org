rud1_not_yet

rud1: not yet implemented

A program written from the spec can end in an error because the form is not built. This file lists those forms by area, in the order of the spec: what the prototype says today, and what to write meanwhile.

Three words are used with one meaning each:

  • built: the prototype does it.
  • decided: designed, a rule of the spec; it waits for a build.
  • proposed: written in the spec, not confirmed by the author.

The Status column has two more: backlog (wanted, not designed) and open (the spec lists the question as open, or two of its lines disagree). A rule that the spec states without a mark counts as decided here. A dash in Status: the spec has no plan for the form as written; the note in Today says more.

The prototype is the one written in Lean, rud1 version 0.1.66; there is no other implementation. Its executable is named rud1_run and files end in .rud; rud1 'code' and rud1 file.rud below stand for a shell function around it.

How to read the tables:

  • Form is a whole program, run as rud1 'code'. Today is all it printed. Run from a file, a position 1:1 shows as file.rud:1:1.
  • L:C error … is a compile error. we exited <state> at L:C is a run that ended in a failed result, with its message in the brackets. Both end with exit status 1.
  • Meanwhile is a program that works today, with its result after \\>. A dash: nothing shorter than writing it out yourself.
  • A form without a row is not thereby built: the list follows the audit of generation 30 and the spec's own marks.

Declarations and types (spec §4, §6)

Declared types are built (generation 45): a declaration, a parameter, a return type (my(sint f(uint a)= a + 1)) and a group type (sint my(a= 1, b= 2)) cast the value to the type, along the promotion diamond. Policies and configuration (spec §8, §9a)

The spec lets a policy (of a company, of a project) turn a warning into an error or into silence. The switches, the configuration file (its format is open) and strict mode (open) are not built: rud1_run has no option for one (rud1_run -h lists -c, -e, -f) and no form in a program sets one. Known limits of the prototype

  • Fuel and steps. A run has a budget of evaluation depth, 100000 by default, and one of steps, 1000000000 by default: a round of a loop and a call take a step each. A loop and a chain of tail calls take no depth; a recursion that is not a tail call does, and about 15000 levels of it use the budget up, and what was written before is lost with it.
    [rud1] say("start"); my(f(n)= if(0 == n, 0, 1 + __SELF__(n - 1))); f(20000) \\ out of fuel
  • rud1_run -f N sets the depth, rud1_run -s N the steps. The same program with -f 1000000:
    [rud1] say("start"); my(f(n)= if(0 == n, 0, 1 + __SELF__(n - 1))); f(20000)
    \\ start
    \\ 20000
  • Indexing a list is linear in the index, and a list made by a range or a comprehension is by name: it is computed again at each use (decided: memoized). So a loop over the indices is quadratic.
    [rud1] my(N= 2000, L= [1..N]); mut my(s= 0); for(i <- [0..N-1], s+= L[i]); s \\ 2001000
  • A walk is linear.
    [rud1] my(N= 2000, L= [1..N]); mut my(s= 0); for(x <- L, s+= x); s \\ 2001000
    On the machine of this run the first took 6.1 s and the second 0.02 s; with N= 4000 the first took 22 s.
  • read_line() in a loop is quadratic in the number of lines. On 4000 lines abcdefghij (yes abcdefghij | head -4000):
    [rud1] mut my(n= 0, l= read_line()); while(is_defined(l), n+= 1; l= read_line()); n \\ 4000
    That took 0.17 s; 8000 lines 0.60 s, 16000 lines 2.16 s.
